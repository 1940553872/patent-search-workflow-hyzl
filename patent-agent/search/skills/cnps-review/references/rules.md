# REVIEW 术语与复核规则

## L0 术语

- 独立上下文：未参与该批初次取证的执行上下文，重新读取冻结原始材料与证据；不是换模型名称或改上下文字符串。
- 拟匹配：程序依据初次证据拟归入匹配、但尚需独立复核的记录。
- 语义排除：排除依据包含技术特征“明确相反”的判断；必须复核对应原文和逻辑。
- 确定性排除：日期、机构、类型等结构化硬条件明确 FAIL 导致的排除；抽样由程序按原因分层选择。
- `confirm`：当前意见与已核实材料一致；`revise`：需要修改或补充，不等于已经完成修改。

## L1 规则、来源与适用范围

来源：用户设计稿第二、三、六、七、八节。适用于新颖性检索结果复核，不替代后续查新或代理师的法律判断。

- 拟匹配全部复核；语义排除全部复核；确定性排除默认每个原因层抽 10%，每层至少 1 条，实际以任务包清单和冻结配置为准。
- 每条肯定技术判定均需公开版本、位置与逐字引文。引文存在只是必要条件，还需判断是否完整支持特征及其关系。
- 同一文件包含多个实施例或互斥选项时，不能自动视为同一方案；从属权利要求须核对引用链，不拼接互不引用且不兼容的方案。
- 修正最多 2 轮是设计初值；仍有争议保留待核实并记录未完成范围，不能改阈值、改规则或强行通过。
- 真实任务匹配精确率需要人工确认样本，附 Wilson 区间；该区间是根据样本量反映估计不确定性的范围。没有人工样本时不计算、不冒称达到 85% 目标。

## L4–L6 检查点

意见对应一份冻结快照。若证据或规格已更新，旧意见不可覆盖新数据。记录问题属于版本绑定、材料不足、取证定位、方案拼接、逻辑树还是日期边界，方便程序只重算受影响部分。复核员不直接编辑数据库或生成最终交付清单。
