# MATCH 术语与证据标准

## L0 术语

| 字段或术语 | 含义 |
| --- | --- |
| `key` | 一份公开文本的唯一键，含公布机构、号码、种类码 |
| `document_sha256` | PDF 字节内容的校验值，用于确认读取的是同一文件版本 |
| `page` | PDF 文件中的页序号，从 1 开始；不等于印在纸页上的页码 |
| `loc` | 原文权利要求号或段落号；无此编号时当前自动定位无法验证，应补证或保留待核实 |
| `scheme` | 证据所属的同一技术方案；不同实施例、互斥选项不能共用标识掩盖差异 |
| `read` | 证据中的实际阅读深度，中文枚举：摘要、权利要求、全文；与请求的英文 read_scope 分开 |

## L1 规则、来源与适用范围

来源：用户设计稿第二、三、四、七、八节。适用于新颖性检索的特征对照，不输出授权、无效或侵权法律结论。

| 证据状态 | 何时使用 | 三值 |
| --- | --- | --- |
| 有支持 | 同一方案原文直接支持整个特征，含其关系和限制 | PASS |
| 明确相反 | 原文明确否定该特征或规定与该特征相反的关系 | FAIL |
| 部分支持 | 仅支持部分对象、步骤、阈值或关系 | UNKNOWN |
| 未找到 | 在实际可读范围内没有找到足够支持或相反证据 | UNKNOWN |
| 材料不可得 | 缺少需要的正文、页面，或文本无法可靠读取 | UNKNOWN |
| 来源冲突 | 同一字段或文本对应关系存在无法解决的冲突 | UNKNOWN |

OR、AND、NOT 的最终逻辑值由程序计算。特征的状态要对应该特征的完整文字，不能为了凑齐 AND 把“部分支持”改成“有支持”。同一段引用可涉及多个特征，但每项独立记录位置和关系。

全文包括权利要求、说明书及必要附图；只拿到摘要不得记为 `全文`。调用方指定 `read_scope: claims` 时按范围阅读并记录限制，不自动宣称已完整排除说明书中的公开。来源冲突不能通过选择更有利的来源消除。

## L5–L6 观测

证据定位完整率 = 同时有公开版本、位置和逐字引文的支持或相反判定数 / 需要这类证据的判定数。该值只衡量可定位性，不等同于匹配精确率。取证失败要能区分“原文没有读到”“文本读不清”“读到但语义不完整”，便于后续只补缺少的材料。
