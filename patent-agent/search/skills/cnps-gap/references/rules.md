# GAP 术语与停止规则

## L0 术语

- 补检 `retrieve`：为未覆盖的技术路径或截断结果增加查询，不变更需求。
- 补证 `evidence`：为现有候选取得缺少的全文、页段或可核实来源。
- `coverage_complete`：必需查询已完成，且没有未解决的截断或失败；不表示数据库全部相关文献都已找出。
- `screening_complete`：候选已按规则归入三类；待核实也属于已经归类。
- `review_complete`：约定复核范围已完成，不等于全文判断永远不会有错误。

## L1 规则、来源与适用范围

来源：用户设计稿第二、七、八节及本次人工网页采集约束；适用于新颖性路径的 GAP 决策。

- 补检和补证合计最多 3 轮是设计默认值，实际用任务包的冻结参数。不得自行重置轮数。
- 默认每轮 12 条查询、2000 篇候选，复核预留 20% 预算；这些是调度参数，不是证明检索质量的阈值。
- 预算到点停止派发新任务。用户网页查询、导出与放置 PDF 的等待由程序挂起，不应消耗工作时限。
- 没权限或语法不支持时不能盲目重试。将问题写入原因，由程序或用户选择已有许可能力；不得悄悄丢弃限制条件。
- 单篇材料问题不阻断其余文献。已完成部分可以交付；任一适用完成标志为否，结果状态为 PARTIAL。

## L4–L6 决策记录

优先修补可明确定位的缺口，避免重复召回已处理的大批文献。记录缺口属于“计划未覆盖”“采集未完成”“材料不足”还是“语义未知”，便于后续归因。所谓“已无有效补检路径”需要说明已尝试的路径与剩余限制，不能从零新增直接推导“已经查全”。
