# SPEC 术语与规则

## L0 术语

| 术语 | 本项目含义 |
| --- | --- |
| 技术特征 `fid` | 一项可在文献中核对的技术要求；编号用于追踪，不代表权利要求编号 |
| 硬条件 `hard` | 必须满足的条件，按用户指定逻辑组合；只有明确 FAIL 才排除 |
| 偏好 `soft` | 影响展示顺序，不改变候选去留的条件 |
| 基准日 `base_date` | 按检索意图选取的比较日期，不等于数据库抓取日期 |
| 公开号 | 一份公开文本的标识；包含公布机构、号码和种类码 |
| 申请号 | 一件申请的标识；不能直接代替某一版全文的公开号 |
| `read_scope` | 调用方要求的阅读深度；实际读到的深度另记在证据中 |

## L1 规则、来源与适用范围

以下规则来源于用户提供的《Agent 中国专利检索筛选工作流-软件设计（D4 工程方向）》第二、三、六、七节，仅用于本项目的检索筛选。

- 新颖性：公开日在基准日前的文献进入现有技术分支；中国申请在基准日前申请、在基准日当日或之后公开，进入抵触申请候选分支并保持待核实。两个分支是 OR，不可将所有晚公开文献一概排除。
- 全景：无默认日期截止，不作技术匹配分类；不得套用新颖性基准日。
- 侵权风险：以当前日期为准，筛选中国有效与审中候选并取得独立权利要求，后续等同判断不在本系统范围。
- AND：任一 FAIL 则 FAIL；全 PASS 则 PASS；其余 UNKNOWN。OR：任一 PASS 则 PASS；全 FAIL 则 FAIL；其余 UNKNOWN。NOT：PASS 与 FAIL 互换，UNKNOWN 不变。
- 用户表达不清时，独立运行待用户确认；被调用运行把待确认事项写入 `needs_human`，不把猜测变成硬约束。

## L4–L6 约束

程序校验字段类型、条件引用和树结构；Skill 负责条件是否忠实表达需求。修改某项条件后，重算范围由程序根据依赖关系确定，Skill 不得删除旧原始记录或重写 trace。
