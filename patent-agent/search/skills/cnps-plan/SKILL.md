# 术语扩展与检索计划

## 1. 适用范围

为 `search` 的三个意图编制查询；每条查询都指向已存在的技术特征。L2 边界是规格中确定的技术主题与数据源能力；L3 目标是把规格变成用户在智慧芽普通检索页面执行、可追踪完成情况的确定检索式。不执行网页操作，不读取账号凭证。

## 2. 输入要求

- 当前 `data/runs/<run_id>/agent_task.json`，`stage` 必须为 `PLAN`。
- 任务包中的最新 `input.spec`、已有查询及其执行状态、数据源能力和预算；补检时还需程序提供的缺口信息。
- 没有规格、特征引用不明或入口为 `lookup`：报告路由问题，不自行生成筛选计划。规格有待确认项时，不把待确认项作为必需查询的限制条件。

## 4. 执行步骤

1. 按 F1…Fn 理解技术对象、机制、关系和效果，扩展专利惯用词。保留原词；不要把不同机制当作同义词。
2. 生成整体组合与必要子机制等互补路径。组内同义词 OR，组间 AND；不要要求每一条查询同时含全部特征，造成过窄召回。每条记录 `fids`，覆盖所有必要技术特征。
3. 默认生成 `search_mode: "expert"` 的 `query`，使用官方支持的字段、英文半角括号、大写 AND/OR/NOT 和英文双引号；英文多词短语必须加引号。`purpose` 单独说明本条查询目的，不能混入可复制检索式。不生成智慧芽 Agent 提示词。字段与范围按 references/rules.md 核对；程序负责结构校验，校验通过不等于已在平台执行。分类号仍须有官方名称和核对来源。
4. 按核心机制与互补组合编写查询，避免把全部特征及场景同时作为每条检索式的 AND 限制。新颖性采集默认不另加公开日和当前法律状态过滤，日期分支由本地程序处理。检索字段、受理局和词组必须明确；用户登记实际式、日期、总数和导出数量。不要把关键词命中作为最终匹配结论。
5. 遵守任务包的查询数量和候选预算。保持历史 `qid`，新增查询使用未使用过的编号；补检只加查询，不改 `spec`。达到上限时列明未覆盖项，不借合并查询掩盖数量。
6. L4 交接：把计划按下述外层结构写入任务包的 `result_path`，执行 `python run.py submit <run_id> PLAN <结果文件>`。校验失败按报错修正；成功后运行 `python run.py queries <run_id>` 生成检索式及共同操作说明，用户在普通搜索页面执行。不得把“已生成检索式”记成“已执行查询”。

## 5. 禁止动作（红线）

- 不调用未授权 API、不抓取网页、不绕过登录或限额，不把待执行或失败的查询登记为零命中。
- 不更改硬条件、阈值、意图、预算或白名单；偏好不能成为排除条件。未知字段仍为 UNKNOWN，只有硬条件明确 FAIL 才排除。
- 未公开技术内容只允许由用户发往配置白名单内的数据源或模型；不能自行向外部服务发送完整需求。
- 不跨文献或跨实施例拼凑特征，不用摘要、关键词共现或相似度作肯定判定；后续肯定判定必须有同一公开文本、同一方案的逐字引文与位置。
- 不互换公开日、申请日和优先权日；抵触申请候选必须保留为待核实。
- 不直接调用其他 Skill，不改运行状态或原始导出。三类结果及数量守恒由程序计算。

## 6. 输出要求

结果文件使用统一封装：`{"task_token":"原样复制当前任务包值","model":"codex","context_id":"实际上下文标识","elapsed_seconds":0,"output":{...}}`；本阶段内容只放入 `output`。

`output.queries` 每条包括 `qid`、`query`、`purpose`、`search_mode: "expert"`、`fids`、`required` 和 `source: "patsnap_web"`。`query` 是完整可复制字段检索式，`purpose` 是供用户阅读的简短目的；不要返回旧字段 `prompt`。共同操作说明及导出字段由程序生成。使用分类号时，在 `classifications` 写 `code`、`official_name`、`verified_url`；不使用则省略。不编造命中数、实际检索时间或结果链接。

模型服务标识沿用当前任务包批准的 `model`（首版为 `codex`）；`elapsed_seconds` 填实际 Agent 工作秒数，不包括等待用户的时间，示例中的 0 不能替代计时。`context_id` 必须真实对应本次执行上下文。

## 7. 完成标准

- L5：所有必要特征至少绑定一条必需查询；查询编号唯一；查询数量不超过任务包预算；提交校验通过。
- L6：每条查询能追溯到规格中的特征及后续导出批次；程序记录输入快照、版本和提交日志。
- 检索式通过字段、操作符、括号及引号结构校验。此处完成只表示计划就绪；`coverage_complete` 必须由实际执行状态计算，不在 Skill 中宣布“查全”。

## 8. 示例

F1 是“检测电解液泄漏气体”，F2 是“监测电压突降”。可生成 `TACD_ALL:("气体传感器" OR "气体探测单元") AND AUTHORITY:(CN)` 及 `TACD_ALL:("电压骤降" AND "气体检测") AND AUTHORITY:(CN)` 等互补路径。错误做法：仅查原句，或把“电池健康评估”无条件当成“电压突降”的同义词。
